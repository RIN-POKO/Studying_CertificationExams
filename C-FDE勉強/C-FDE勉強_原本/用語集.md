# 用語集（Claude FDE Core）

Core 4 コースで登場する重要用語を、混同しやすいポイントとあわせて整理しています。暗記テスト機能（HTML 版の「暗記マスク」）と組み合わせて確認してください。

## 1. AI の能力と限界

| 用語 | 意味 | 混同・注意ポイント |
| --- | --- | --- |
| **Next-Token Prediction** | 文脈に続く最も確率の高い次のトークンを予測し続ける生成原理 | 「意味を理解して論理検証している」のではなく確率予測であるため、真偽検証は別工程が必要 |
| **Context Window** | 1 回の推論で参照できる入力・出力トークンの総容量 | 上限に収まっていても、長大になるほど途中の指示が薄れる（Contextual Drift） |
| **Hallucination** | 事実や根拠がない内容を、もっともらしく出力する現象 | モデルの悪意ではなく確率生成の性質。根拠資料の提示と不明時の回答保留で抑える |
| **Contextual Drift / Context Rot** | 会話や入力が長くなるにつれ、初期指示や制約への注意が落ちて品質が下がる現象 | 履歴を無制限に積むのではなく、整理・要約・セッション分割で防ぐ |
| **Parametric Memory** | 事前学習を通じてモデルの重みに蓄えられた知識 | 社内ルールや最新情報は含まれないため、検索やコンテキスト付与が必要 |
| **Non-deterministic** | 同じ入力でも毎回まったく同じ出力になるとは限らない性質 | 再現性・厳密性が必須な計算や状態遷移は決定論的コードへ任せる |

## 2. AI Fluency と 4D Framework

| 用語 | 意味 | 混同・注意ポイント |
| --- | --- | --- |
| **AI Fluency** | AI と有効・効率的・倫理的・安全に協働する実践的能力 | 派手なプロンプト集を覚えることではなく、人間が主導権を握る設計・運用力 |
| **4D Framework** | Delegation / Description / Discernment / Diligence の 4 要素 | 1 つでも欠けると「丸投げ」「手戻り」「品質劣化」「事故」につながる |
| **Delegation（委任）** | 何を AI に任せ、何を人間が担うかを決める判断 | 実装の下書きは委任できるが、要件やセキュリティの最終判断は委任しない |
| **Description（記述）** | 求める内容・進め方・振る舞いを明確に言語化すること | Product / Process / Performance の 3 視点を揃えると手戻りが減る |
| **Discernment（識別）** | AI の出力の正しさ・品質・前提の妥当性を批判的に評価すること | テストが通っただけで中身を読まないのは Discernment 不足 |
| **Diligence（責任）** | 安全性・プライバシー・ライセンス・説明責任を含めて出荷を担保すること | 「AI が書いたから分からない」はプロとして通用しない |

## 3. Claude プラットフォーム基盤

| 用語 | 意味 | 混同・注意ポイント |
| --- | --- | --- |
| **Anthropic API（1st-party）** | Anthropic が直接提供する API / Console 環境 | 最新機能やモデルの反映が最も早い |
| **Amazon Bedrock** | AWS 上で Claude を動かすマネージドサービス | AWS IAM・閉域網・請求統合が必須な企業で選ばれやすい |
| **Google Cloud Vertex AI** | GCP 上で Claude を動かすプラットフォーム | GCP 統制・BigQuery 連携・GCP 契約を重視する企業で選ばれやすい |
| **Stateless API** | 各リクエストが独立し、サーバーが会話履歴を自動保持しない設計 | 毎回履歴を送るため、長会話ではトークンと遅延が増える前提で設計する |
| **Tool Use** | モデルが必要に応じて外部ツール呼び出しを構造化形式で要求する機能 | 社内 DB 参照や最新データ取得に必須。全データをプロンプトに貼る代わりに使う |
| **Vision** | 画像や図表付き PDF などをコンテキストとして直接読み取る能力 | OCR 前処理を簡素化できる場合があるが、トークン消費と精度確認は必要 |

## 4. モデル選定

| 用語 | 意味 | 混同・注意ポイント |
| --- | --- | --- |
| **Claude Opus** | 最高難度の推論・長時間の自律コーディング向けフラッグシップ | 全タスクに使うとコストと遅延が過大になるため、高難度タスクに絞る |
| **Claude Sonnet** | 高い知能と高速な応答を両立するバランス型主力モデル | 多くの企業アプリ・開発支援における標準の起点 |
| **Claude Haiku** | 最速・最安価な軽量モデル | 大量分類・抽出・ルーティング向き。複雑な多段階推論には不向き |
| **Effort Parameter** | 同一モデル内で推論に使う計算量（思考の深さ）を調整する設定 | 上位モデルへ即座に変える前に、Effort 調整で品質と速度の折り合いを探れる |
| **Efficiency-First** | 軽量モデルから始め、不足分だけ上位モデルへ上げる進め方 | 大量処理や厳しいコスト・遅延制約が明確な案件に向く |
| **Capability-First** | 高性能モデルでまず成立性を証明し、後から最適化する進め方 | 難易度が高く、まず価値実証（PoC）を成立させたい案件に向く |

## 5. デリバリーメソドロジー（Delivery Methodology）

| 用語 | 意味 | 混同・注意ポイント |
| --- | --- | --- |
| **Use-Case Qualification** | 顧客課題が LLM / エージェント適用に適しているかを見極める工程 | 全要望をそのまま受けず、価値・技術適合性・検証可能性で選別する |
| **Baseline Metrics** | AI 導入前の現状値（時間、コスト、エラー率等）の定量記録 | 導入後に効果を証明するため、実装前に必ず計測しておく |
| **Success Metrics** | パイロットの成否を判定するために事前合意する目標数値 | 曖昧な感想ではなく、数値の合格ラインを関係者と合意する |
| **First Slice** | 全体構想のうち、短期間で価値実証しやすい最小の初期範囲 | 全社一括ではなく、効果と制御性のバランスが良い切り口から始める |
| **Delivery Plan Pack** | 適格性評価、パイロット設計、ROI Scorecard、リスク計画をまとめた標準資料 | 期待値合わせと本番移行判断の根拠として作成する |
| **ROI Scorecard** | 投資コストと期待効果を定量比較する評価表 | 開発・API 費用だけでなく、現状 Baseline との差分を示す |

## 6. エンタープライズ導入の推進（Driving Enterprise Adoption）

| 用語 | 意味 | 混同・注意ポイント |
| --- | --- | --- |
| **30-Day Fade** | 導入直後 2〜3 週間の盛り上がりの後、1 か月前後で利用率が急落する現象 | ツール配布だけでは防げず、導入後の定着支援が必要 |
| **Champion Network** | 各部門の推進役を配置し、現場の質問対応や事例共有を担わせる仕組み | IT 部門の一方的な案内より現場への浸透が早い |
| **Role-Based Training** | 職種ごとの実業務シナリオに即したトレーニング設計 | 全社一律の一般デモより業務定着につながりやすい |
| **Workload Expansion** | パイロット成功後に、隣接チームや他部門へ適用範囲を広げる展開戦略 | 部門の準備度と価値の大きさで優先順位を決めて進める |
