# 用語集

5つの技能で使う言葉だけを集めました。「ひとことで」で意味をつかみ、「まちがえやすい点」で隣の言葉との違いを確かめてください。章番号は、詳しく説明している章です。

## 第1章 ループとオーケストレーション

| 用語 | ひとことで | まちがえやすい点 |
| --- | --- | --- |
| ハーネス | モデルを呼び、ツールを実行し、結果を会話に足すプログラム | モデル自身はツールを実行しない |
| `stop_reason` | 返答が止まった理由。ループの分岐に使う | 完了の判断はこの値で行う。文章ではない |
| `tool_use` | 「ツールを実行して」という停止。実行して続ける | 文章が付いていても、まだ途中 |
| `end_turn` | 「返答を終えた」という停止。ループを閉じる | 空の文や「完了しました」という語とは別 |
| ツール結果 | ハーネスが会話履歴へ戻す、ツールの戻り値 | 戻さないと、次の呼び出しは結果を見られない。モデルに隠れたメモリはない |
| `max_tokens` による切断 | 出力の上限で返答が途中で切れた状態 | `end_turn` ではない。切れたツール引数は実行しない |
| コーディネーター | 分解・委任・集約・再委任を担う親 | サブエージェントどうしは直接つながない |
| サブエージェント | 別の会話で、渡された依頼だけを処理するエージェント | 親の履歴は引き継がず、呼び出し間でメモリも共有しない |
| Agent ツール | サブエージェントを起動するツール（旧称 Task） | Agent ツールが使えない状態だと、委任は文章のままで誰も起動しない |
| `allowedTools` | 列挙したツールを承認なしで実行させる設定 | 使えるツールを**絞る設定ではない**。絞るのは `tools` や `disallowedTools`。スキルの `allowed-tools`（ハイフンあり）は別物 |
| `disallowedTools` | 書いたツールを定義ごとリクエストから外す | Claude はそのツールを見ることも呼ぶこともできない |
| `maxTurns` / `max_turns` | `AgentDefinition` ごとのターン上限 / `query` 全体のターン上限 | 上限で終わるとタスクは途中のまま。必須の処理はループの外のコードで確認する |
| フォーク（サブエージェント） | 親の会話をコピーして始まる子 | 親の文脈を子に持たせる仕組み。子の途中結果を親に戻す仕組みではない |
| Messages API のステートレス性 | API は前のリクエストを覚えていない | 会話を続けるには、アプリが履歴をすべて毎回送る |
| `AgentDefinition` | 種類ごとの説明・システムプロンプト・ツール制限 | 説明が広いと、コーディネーターの選択が揺れる |
| 前提条件ゲート | 前の手順の事実が状態に入るまで、後のツールを実行しない検査 | プロンプトは従う割合を上げるだけ。ゲートは外れた回の副作用を止める |
| 実行前フック（呼び出しの遮断） | ツール実行の前に、規則違反の呼び出しを止める | 例：閾値を超える返金をAPIを呼ばずに人へ回す |
| `PostToolUse` | ツール実行の後、モデルが読む前に結果の形を整える | 実行前フックとはタイミングが違う。止める役ではなく、そろえる役 |
| ハンドオフ | 会話ログを見られない人に渡す、判断に必要な構造 | 顧客・何が起きたか・金額・推奨する次の行動。全文の貼り付けではない |
| プロンプトチェーン | やることが決まっている仕事を、段階ごとに順に処理する | 例：ファイル単位のレビュー → 横断のレビュー |
| 動的な分解 | 途中の発見に応じて次のサブタスクを足す | 調査向き。決まったレビューに使うとチェックリストを捨てて探索に流れる |
| `--resume` | 名前を付けた過去の会話を履歴ごと再開する | 履歴のツール結果が今も正しいときだけ。変わったファイルは名指しで読み直させる |
| `fork_session` | 同じ地点から枝分かれさせ、別案を混ぜずに比べる | 履歴が古いときの「新規セッション」とは別の問題 |
| カバレッジの穴 | 下流は全員成功だが、分解に入っていなかった領域が成果物にない状態 | 下流の精度を上げても出てこない。直すのはコーディネーターの分解 |

## 第2章 ツールとMCP

| 用語 | ひとことで | まちがえやすい点 |
| --- | --- | --- |
| ツール説明 | モデルがツールを選ぶ決め手 | 目的・入力の形・例・端のケース・使わない場合を書く。名前だけ変えても効果は薄い |
| `isError` | 「この結果は失敗」と伝えるフラグ | 本文に「失敗」とあっても、フラグがないと成功として読まれることがある |
| `errorCategory` | 失敗の種類 | 一時的（transient）・検証（validation）・権限（permission）・方針（policy） |
| `isRetryable` / `retriable` | 同じやり方で再試行してよいか | 綴りはどちらも使われる。方針違反・権限・検証では偽 |
| 有効な空結果 | 成功したが該当がゼロ件 | `isError` にしない。タイムアウトの空と混ぜると、穴が「無かった」という結論になる |
| `tool_choice: auto` | 文章で答えてもよい | 抽出に使うと表が文章になり、パーサが失敗する |
| `tool_choice: any` | どれかのツールを必ず呼ぶ | どれを呼ぶかはモデル。スキーマが複数で種類が不明なとき |
| 強制ツール選択 | 指定したツールをそのターンで必ず呼ぶ | 先頭の1段だけ。外す条件は「成功したこと」 |
| `.mcp.json` | リポジトリで共有するMCPの設定 | 秘密は書かず、`${GITHUB_TOKEN}` のような参照だけ |
| MCP のスコープ | ローカル（既定・本人・このプロジェクトだけ）、プロジェクト（`.mcp.json`・チーム共有）、ユーザー（本人・全プロジェクト） | ローカルとユーザーは `~/.claude.json` に保存。`~/.claude/CLAUDE.md` とは別のファイル |
| プロトコルエラー（MCP） | 不明なツールや不正な要求に使う JSON-RPC のエラー | ツールが動いたあとの失敗は、`isError: true` のツール実行エラーで返す |
| MCP プロンプト | 利用者が選んで実行する指示のテンプレート | Claude Code では `/mcp__サーバー名__プロンプト名` で実行できる |
| MCPリソース | 「何があるか」のカタログ（読むだけ） | 操作をリソースにすると、読むだけで副作用が起きたように見える |
| MCPツール | 取得や更新などの操作 | カタログをツールにすると、同じ一覧が履歴に積み上がる |
| Grep | ファイルの中身をパターンで探す | 入口探しの最初の一手。パスだけの探索には使わない |
| Glob | パスや拡張子でファイルを探す | 中身は見ない |
| Edit | 一意な文字列を錨にして部分修正 | 錨が2か所に一致したら失敗する。失敗を成功と偽らない |
| Read / Write | ファイル全体の読み書き | Edit の錨が一意でないときの次の手は、Read してから Write |
| Bash | シェルコマンドの実行 | テスト実行に使う。中身の検索や置換の代わりにはしない |

## 第3章 設定とワークフロー

| 用語 | ひとことで | まちがえやすい点 |
| --- | --- | --- |
| 利用者レベルの `CLAUDE.md` | `~/.claude/CLAUDE.md`。その人のセッションだけに効く | クローンしても配られない |
| プロジェクトの `CLAUDE.md` | `.claude/CLAUDE.md` またはルートの `CLAUDE.md` | 共有したい指示の置き場所 |
| ディレクトリの `CLAUDE.md` | そのサブツリーを触るときの指示 | あちこちに散らばったファイルを1枚で覆うことはできない |
| `.claude/rules/` の `paths` | glob に一致するファイルを編集したときだけ読む規約 | 散らばったテストへの規約は、ディレクトリの複製よりこちら |
| `@import` | 必要な標準ファイルだけを取り込む | 全員に全標準を読ませない |
| `/context` | 今のセッションのコンテキストの内訳。Memory files に読み込まれた指示ファイルが出る | 指示が届いているかは、推測せずここで確かめる |
| `/memory` | メモリファイルの場所を一覧し、エディタで開く | 読み込まれたかの確認ではない |
| `CLAUDE.local.md` | リポジトリ内に置く個人用の指示 | バージョン管理に含めない |
| `.claude/commands/` | 以前のカスタムのスラッシュコマンドの置き場所 | 今はスキルと同じ仕組みとして扱われる |
| `--append-system-prompt` / `--system-prompt` | 既定のシステムプロンプトに追加 / 置き換え | 置き換えると、既定のツールの使い方や規約が消える |
| `--bare` | フック・スキル・MCP・`CLAUDE.md` の自動検出などを省く最小構成 | 必要な設定はフラグで明示的に渡す |
| `REVIEW.md` | Code Review 専用の指示（ルートに置く） | ベースブランチから読まれる |
| スキル | `.claude/skills/` の `SKILL.md`。必要なときだけ読む手順 | 常に守らせたい規約をスキルに入れると、呼び忘れたときに消える |
| `context: fork` | スキルを別の会話で実行し、結論だけ戻す | 探索の長いログから本会話の予算を守る |
| `allowed-tools` | スキル実行中だけツールを絞る | SDK の `allowedTools` とは別 |
| `argument-hint` | 引数なしで呼ばれたとき、必要な引数を尋ねるヒント | ないと対象を推測して走る |
| プランモード | 変更の前に境界と手順を文章にする進め方 | 大きい変更・複数の案・多数ファイル・サービス境界に使う |
| 直接実行 | 調査を挟まず適用する進め方 | 変える場所が1つのシンボルに特定できているとき |
| Explore | 長い調査を外で行い、ファイル名と結論だけ戻すサブエージェント | 生の検索結果を本会話に積まない |
| `-p` / `--print` | 結果を出して、入力を待たずに終了する起動 | CI で入力待ちを防ぐ。`--batch` や「ヘッドレス」環境変数は存在しない |

## 第4章 プロンプトと構造化出力

| 用語 | ひとことで | まちがえやすい点 |
| --- | --- | --- |
| 明示的な基準 | 報告する欠陥と捨てる指摘を、種類とコード例で定義したもの | 「慎重に」や確信度の自己申告は代わりにならない |
| 重大度 | 段階ごとに、どんなコードが入るかを定義したもの | 「高」という語だけだと、人によって段階が変わる |
| few-shot | 判断と出力の形を見せる具体例。公式の目安は3〜5個 | 関連性があり互いに違いのある例にする。選ばなかった代替の理由を添える |
| 構造化出力（structured outputs） | 応答を JSON スキーマに従わせる機能 | 保証するのは形と型。値の意味や表記のそろえ方は保証しない |
| 引用（citations） | 回答が渡した文書のどこに基づくかを示す | 渡した文書の範囲しか示せない |
| nullable | 文書にない値を空で返してよい欄 | 必須にすると、近くの数字をコピーして埋める |
| `unclear` | 読んだが判別できない、という値 | 空文字にすると「未抽出」と区別できない |
| `other` と詳細 | 既存の分類に入らないものを受ける形 | 未知を既存の分類に押し込むと、件数が混ざる |
| strict | スキーマへの厳密な準拠。構文の破れを拒否 | 合計の不一致のような意味の正しさは保証しない |
| 意味的な検証 | スキーマを通ったあとに残る矛盾の検査 | 例：声明の合計と、明細から計算した合計の比較 |
| `conflict_detected` | 情報源どうしが矛盾している印 | どちらかを黙って捨てない。再試行で消えない矛盾は人手へ |
| `detected_pattern` | 指摘のもとになったコードの形 | 却下を集計し、どの形が誤検知かを基準の改善に戻す |
| Message Batches API | 費用がおよそ半分の非同期処理 | 最大24時間・遅延保証なし・途中のツール往復は不可 |
| `custom_id` | バッチの依頼と応答を結ぶ識別子 | 失敗の再送は新しい識別子で、元の識別子を参照欄に残す |
| セルフレビュー | 生成したのと同じ会話で見直すこと | 生成時の理由が残り、それを擁護しやすい。別の実行でレビューする |
| マルチパス | ファイル単位の局所パスと、横断のパスに分けるレビュー | 入力を小さくして、注意の偏りをそろえる |

## 第5章 コンテキストと信頼性

| 用語 | ひとことで | まちがえやすい点 |
| --- | --- | --- |
| ケースの事実（事実ブロック） | 金額・日付・番号・状態 | 要約の外に置き、毎回プロンプトに入れる。要約するのは経緯だけ |
| lost in the middle | 長い入力の真ん中を見落としやすい現象 | 但し書きは先頭の事実ブロックにも1行置く |
| 方針の空白 | 規程がその要求について何も書いていない状態 | 「複雑に見える」とは別。エージェントが承認すると、書いていない規則を作ることになる |
| スクラッチパッド | パス・シンボル・呼び先・未解決の問いを書き残すファイル | 散文ではなく行で書く。会話が一般論しか言わなくなっても、ここから具体に戻れる |
| `/compact` | 探索で埋まった会話を要約して短くする | 圧縮は要約なので、残す行を先にファイルへ出してから行う |
| マニフェスト | エージェント名・状態ファイル・最後に成功したフェーズの索引 | 落ちたあとは、ここから次のフェーズを起動する |
| 層化抽出 | 文書の種類と欄ごとに、確信度の高いものも含めて誤り率を測る抜き取り | 全体の平均は、件数の多い簡単な種類に引っ張られる |
| 校正 | 確信度の申告と、ラベル付きデータでの実際の正解率を対応づけること | 申告0.9でも実際0.6なら、自動採用の線にはしない |
| スライディングウィンドウ | システムプロンプトと直近の一定数のターンだけを送る | 直近しか参照しない会話で最も単純。古い情報は消える |
| コンテキストの劣化（context rot） | トークン数が増えるほど精度と想起が下がる性質 | 大きいウィンドウのモデルやキャッシュでは解消しない。量を減らすか外に書き出す |
| 初回解決 | その場で対応できることを完了させる考え方 | 解決を申し出るときは引き継ぎの選択肢も示す。未完了を完了と伝えない |
| 主張と情報源の対応 | 主張・抜粋・URLまたは文書名・日付の組 | 統合のあとまで保持する。親が自分の言葉で書き直すと壊れる |
