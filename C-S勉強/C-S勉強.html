Claude Sales (C-S) 対策ノート

このノートについて

このノートは Anthropic Partner Academy（Skilljar）の **Claude Sales (claude-sales) ラーニングパスを想定し、パートナー営業・プリセールス・アカウントマネージャーに求められる Sales 固有の知識と判断軸** をまとめた学習資料です。

LLM の基礎（AI の能力と限界・4D Framework・モデル選定）や開発者向け技術（Claude Code・MCP・Agent Skills）は C-FDE勉強 や CCAR-F / CCDV-P で扱うため、本ノートでは 製品ポジショニング・顧客ヒアリング・セキュリティ反論処理・ROI と拡大戦略 に絞って整理しています。

第 1 章 Claude 製品ラインナップと提案の全体像

💡 ヒント

この章のたとえ：同じエンジンを積んだ「個人向け乗用車」「社用車フリート」「組み込み用エンジン」

Claude のモデル知能というエンジンは共通でも、個人のパソコンで使うもの（Free / Pro）、会社全体で安全に管理・統制して使う社用車（Team / Enterprise）、自社の業務アプリやクラウド基盤に直接組み込むエンジン（Anthropic API / Amazon Bedrock / Google Cloud Vertex AI）では、契約・管理・セキュリティの仕組みがまったく異なります。顧客の目的に合った形態を選ぶことが営業提案の第一歩です。

この章のゴール

  • 個人向けプラン（Free / Pro）と法人向けプラン（Team / Enterprise）の決定的な違いを説明できる。
  • SaaS 型（Claude Enterprise）と API / クラウド基盤型（Anthropic API / Amazon Bedrock / Google Cloud Vertex AI）の使い分けを提案できる。
  • Claude の差別化ポイント（安全性・長文コンテキスト・Projects / Artifacts / Claude Code / Connectors）を顧客課題に結びつけて語れる。
  • 社内の Shadow AI（個人アカウントの無断利用）を解消する価値を経営層・IT 部門へ伝えられる。

要点 3 つ

  1. 法人顧客には原則として法人向け契約（Enterprise / Team / 商用 API）を提案する。 個人向けプランを業務利用すると IT 管理や監査ができず Shadow AI の温床になるため、統制可能な商用プランへ誘導する。
  2. 「すぐ業務で使う SaaS」か「自社システムへ組み込む API / クラウド」かで提案軸を分ける。 社員が日常業務で使うなら Claude Enterprise、自社アプリ連携や閉域網統合なら API や Bedrock / Vertex AI を選ぶ。
  3. モデルの性能だけでなく「安全に企業データとつなげる力」を価値として訴求する。 Projects による知識共有、Artifacts による成果物生成、Connectors / MCP による社内ツール連携、Claude Code による開発支援を一体のプラットフォームとして提案する。

用語意味
Claude for Work法人向けに提供される Team プランおよび Enterprise プランの総称

本編

1-1 プラン・提供形態の比較とポジショニング

顧客の規模や利用形態に応じて、適切な提供形態を見極めます。

区分主な対象主な特徴・統制機能提案が向いている場面
Free / Pro（個人向け）個人ユーザー個人単位の課金。組織の SSO や監査ログ管理はない法人提案では原則対象外（Shadow AI 化を防ぐため商用プランへ移行を促す）
Claude Team中小〜中堅チーム共有 Projects、チーム管理、商用データ保護（学習利用なし）数名〜数十名規模で、まずチーム単位の協働を始めたい場合
Claude Enterprise中堅・大企業SSO、SCIM、Enterprise Audit Logs、Compliance API、カスタムデータ保持、Claude Code 統制全社展開、CISO / 法務の監査要件、Shadow AI の一掃が必要な企業
Anthropic API（1st-party）開発チーム・SaaS 事業者最新モデル・機能への最速アクセス、柔軟な API 課金自社プロダクトや社内自動化パイプラインへ直接組み込む場合
Amazon Bedrock / Google Cloud Vertex AIクラウド標準を持つ大企業既存 AWS / GCP の IAM、VPC 閉域接続、クラウド請求・EDP 消化既存クラウドのセキュリティ審査を通過済みの環境で動かしたい場合

1-2 企業顧客へ訴求する 4 つの差別化価値

  1. 安全性と予測可能なガバナンス: 商用プランおよび API では顧客データをモデルの事前学習に利用しない（Zero Training by Default）ことを明確に保証できます。
  2. 長文コンテキストと深い読解力: 契約書、仕様書、コードベースなど大量の資料をまとめて読み込み、整合性を保ったまま分析・作成できます。
  3. 業務に溶け込む機能群: Projects に社内ルールや資料を登録しておけば毎回長い前提を打つ必要がなく、Artifacts で資料やプロトタイプをその場で形にできます。
  4. ビジネスと開発の両輪（Claude Code 連携）: 事務・企画部門の支援だけでなく、Claude Enterprise 配下でエンジニア向けの Claude Code も統合管理でき、全社でプラットフォームを統一できます。

まとめ：どう判断するか

状況避ける選択とるべき選択
従業員が個人の Pro アカウントで社内資料を要約している「便利に使えているならそのまま様子を見ましょう」と放置するShadow AI リスクを指摘し、SSO・監査ログ・学習除外が効く Claude Enterprise への統合を提案する
顧客が「自社アプリにチャットボットを組み込みたい」と相談SaaS 版の Claude Enterprise アカウントを人数分売ろうとするAnthropic API、または顧客のクラウド環境に応じた Bedrock / Vertex AI を提案する
大企業の情報シスが「新規ベンダーの支払い手続きや審査に時間がかかる」と難色1st-party の直接契約だけに固執して商談が止まるすでに契約済みの AWS（Bedrock）や Google Cloud（Vertex AI）経由での調達・EDP 活用を提案する

確認問題

問 1

従業員 3,000 名の企業で、情報システム部門から「現場の社員が勝手に個人向け AI アカウントへ業務データを入力しており困っている。全社で安全に管理できる環境を整えたい」と相談を受けました。最初に提案すべき中心的なプランはどれですか。

A. 社員全員に個人の Pro アカウントを経費精算で契約させる
B. SSO・SCIM・Audit Logs・学習除外を備えた Claude Enterprise を提案し、管理された環境へ移行する
C. 開発者向けの API キーを 1 つ発行し、全社員のブラウザに手動設定させる
D. AI の利用を全面禁止する以外の選択肢はないと伝える

解答

B。Shadow AI を解消するには、IT 部門が認証（SSO / SCIM）と監査（Audit Logs）を統制でき、データが学習に使われない Claude Enterprise へ統合する提案が最適です。

問 2

顧客のエンジニアリング部門が「自社で開発している顧客向け SaaS 製品の裏側に Claude の要約機能を組み込みたい」と考えています。提案すべき提供形態として最も適切なものはどれですか。

A. Claude Enterprise のユーザーシートを顧客のエンドユーザー人数分契約してもらう
B. Anthropic API、または顧客が利用しているクラウド基盤（Amazon Bedrock / Google Cloud Vertex AI）の API を提案する
C. 社員が毎日画面からコピー＆ペーストして要約を返す運用を提案する
D. Free プランのブラウザ画面を iframe で埋め込む

解答

B。自社アプリケーションやサービスへの組み込み用途には、SaaS シートではなく API（Anthropic API / Bedrock / Vertex AI）が適しています。

問 3

ある大手小売企業が「すでに AWS と大型の年間利用契約（EDP）を結んでおり、新規のクラウドサービス調達には厳しい審査と数か月の稟議がかかる」と述べています。営業担当として商談を前進させる最適な提案はどれですか。

A. 審査が終わるまで半年以上待つしかないと伝える
B. Amazon Bedrock 上で Claude を利用する構成を提案し、既存の AWS セキュリティ統制と EDP 契約枠を活用できるようにする
C. 審査を回避するため個人のクレジットカードで API を契約するよう勧める
D. 契約不要な Free プランで本番システムを動かすよう提案する

解答

B。顧客が AWS や Google Cloud の既存契約・セキュリティ統制を重視する場合、Amazon Bedrock や Google Cloud Vertex AI 経由の導入を提案することで調達と審査の障壁を大きく下げられます。

第 2 章 顧客課題のヒアリングと提案設計（Discovery & Solution Positioning）

💡 ヒント

この章のたとえ：症状を聞く前に薬を出さない「総合診療医の問診」

「AI を導入したい」という顧客の言葉は、「何か体調を良くしたい」という相談に似ています。どの業務で何分かかっているのか、誰が決裁者で、どんなセキュリティ制約があるのかを問診（Discovery）で引き出して初めて、Claude Enterprise か API か、どの部門から始めるべきかの処方箋が書けます。

この章のゴール

  • 商談初期のヒアリング（Discovery）で押さえるべき 4 つの観点（業務課題・データ環境・IT 統制・意思決定構造）を説明できる。
  • 部門別の代表的なユースケース（Engineering / Legal / Finance / Sales / Customer Support）に対して Claude の価値を具体化できる。
  • 顧客の環境（SaaS 中心か、AWS / GCP 中心か）に応じて最適な導入経路を選定できる。
  • 単なる「機能の売り込み」ではなく、顧客の経営課題に直結した提案ストーリーを組み立てられる。

要点 3 つ

  1. 「AI で何ができますか？」と聞かれたら、顧客の業務ボトルネックへ質問を返す。 汎用デモを見せる前に、時間のかかっている業務・人手不足の領域・既存データの所在を聞き出す。
  2. 部門ごとの「具体的な痛み」に合わせてユースケースを提示する。 開発なら Claude Code によるコード理解と修正、法務なら契約書レビュー、営業なら提案書作成や CRM 連携など、相手の言葉で価値を語る。
  3. 導入経路とセキュリティ条件を初期段階で特定する。 商談の終盤で「実は AWS 閉域網が必須だった」と発覚する手戻りを防ぐため、早い段階でクラウド方針とコンプライアンス要件を確認する。

30 秒で全体像

flowchart TD
  D[1. Discovery ヒアリング<br>業務ボトルネック / クラウド環境 / 規制要件] --> M[2. 部門別ユースケース選定<br>高頻度・高時間コスト業務を特定]
  M --> R[3. 導入経路の決定<br>Claude Enterprise / API / Bedrock / Vertex AI]
  R --> P[4. 価値提案<br>業務インパクトと安全性の両立]

用語

用語意味
Discovery（課題発掘）提案前に顧客の業務プロセス、課題、数値目標、制約条件、決裁プロセスを聞き出す商談工程
Business Pain顧客が時間・コスト・品質・リスクの面で実際に困っている具体的な業務課題
Champion（社内推進者）顧客社内で導入の必要性を理解し、他部門や決裁者との調整を後押ししてくれる味方
Economic Buyer（決裁者）予算承認と契約の最終決定権を持つ責任者（CIO、CISO、事業部長など）
Land and Expandまず課題が明確な 1 部門・1 ユースケースで導入し（Land）、成果を示して他部門へ広げる（Expand）戦略

本編

2-1 Discovery で必ず確認すべき 4 つの質問領域

  1. 業務と効果の領域: 「現在最も時間や人手がかかっており、AI で改善したい定型・知的業務は何か」「その作業に現在何時間／何人かかっているか」
  2. データと連携の領域: 「参照したい社内文書やナレッジはどこにあるか（Google Drive、SharePoint、Salesforce、GitHub 等）」「機密情報や個人情報・医療情報は含まれるか」
  3. IT・クラウド基盤の領域: 「全社標準のクラウドは AWS / Google Cloud / Microsoft のどれか」「ID 管理（SSO / SCIM）や監査ログ（SIEM）の要件はあるか」
  4. 組織・調達の領域: 「パイロットの成功基準を誰と決めるか」「契約・セキュリティ審査に関わる関係部門（CISO・法務・購買）はどこか」

2-2 部門別ユースケースのマッピング

部門よくある課題（Pain）Claude の提案ポイント
Engineering（開発）レガシーコードの解読、テスト不足、PR レビュー待ちClaude Code や API による調査・実装・テスト支援、技術仕様書の自動整理
Legal（法務）大量の契約書チェック、社内基準との照合に時間がかかる長文コンテキストでの契約条項比較、リスク箇所の抽出と一次レビュー支援
Finance（財務・経理）決算資料・稟議書・請求データの突合と要約作業PDF や表データの読解、異常値や確認ポイントの構造化レポート生成
Sales（営業）顧客リサーチ、商談準備、提案書作成、CRM 更新の負担共有 Projects での提案書ドラフト作成、商談メモの構造化とフォロー案作成
Customer Support（CS）複雑なマニュアル検索、一次回答作成、エスカレーション判断社内ナレッジに基づく回答下書き生成、問い合わせ分類による処理時間短縮

2-3 Land and Expand を意識した初期スコープ提案

最初の商談から「全社全業務を一気に変えましょう」と提案すると、意思決定が重くなり失注しやすくなります。

  • Land（着地）: 効果が測りやすく推進意欲のある 1〜2 部門を選び、明確な成功指標を置いて小さく確実に成果を出す。
  • Expand（拡大）: 初期部門で得た削減時間や品質データを社内事例として使い、隣接部門や全社ライセンスへ拡大する。

まとめ：どう判断するか

状況避ける選択とるべき選択
顧客が「とりあえず Claude の機能デモを全部見せてほしい」と依頼相手の業務を聞かずに全機能を 1 時間説明し続ける最初の 10 分で対象部門・課題・クラウド方針をヒアリングし、関連するユースケースに絞って見せる
営業担当者との商談で盛り上がっているが、IT・セキュリティ部門の要件を確認していない受注間際まで技術・セキュリティ要件の確認を先送りにする初期段階でクラウド標準（AWS / GCP）や審査部門の要件を確認し、後から手戻りしない提案にする
顧客が複数部門での導入を検討しているが、予算稟議が通りにくい最初から全社数千人分の大規模見積もりだけを提示するLand and Expand に沿い、まず効果を示しやすい重点部門でのパイロット提案から入る

確認問題

問 1

ある企業の事業部長から「社内で生成 AI を使いたいので Claude のデモを見せてほしい」と依頼がありました。商談の冒頭で営業担当がまず行うべき対応として最も適切なものはどれですか。

A. 質問は一切せず、用意してきた 50 枚の製品機能スライドを最初から最後まで説明する
B. 対象となる部門や現在時間のかかっている業務課題、社内データの所在、セキュリティ上の制約をヒアリングし、顧客の課題に即したデモへ焦点を合わせる
C. 契約書をその場で提示してサインを求める
D. 最も技術的に複雑な API コードの解説から始める

解答

B。Discovery によって顧客の具体的な業務課題と制約条件を引き出してから関連ユースケースを示すことで、導入後の価値を自分事としてイメージしてもらいやすくなります。

問 2

B. 「長大な契約書や社内法務基準をコンテキストとして読み込み、リスク条項の抽出や一次レビューの所要時間を大幅に短縮できます」
C. 「サーバーの Kubernetes マニフェストを自動デプロイできます」

解答

B。相手の部門（ここでは法務）が日々抱えている契約書レビュー等の課題に直結する価値を提示することが、部門別提案の基本です。

A. 全社予算が下りるまで 1 年間営業活動を停止する

第 3 章 セキュリティとコンプライアンスの反論処理（Objection Handling）

💡 ヒント

この章のたとえ：銀行の金庫室を示すような「安心の根拠提示」

どれほど性能が優れていても、CISO や法務部門は「社外秘データが他社の学習に混ざらないか」「監査ログを追えるか」「医療や金融の規制を満たせるか」という一点で導入を止める権限を持っています。営業が抽象的に「安全です」と言うのではなく、契約条項・第三者認証・管理機能の具体的な仕組みで不安を取り除くことが受注の鍵になります。

この章のゴール

  • 商用プラン・API における Zero Training by Default（学習利用なし）とデータ分離の仕組みを正確に説明できる。
  • SOC 2 Type II、HIPAA / BAA、GDPR / DPA など主要コンプライアンス要件への対応方針を案内できる。
  • SSO / SCIM、Enterprise Audit Logs、Compliance API、Custom Data Retention による IT 統制を説明できる。
  • 顧客（CISO・法務・開発責任者）からよく出る 5 つのセキュリティ反論に対して的確に切り返せる。

要点 3 つ

  1. 商用プラン・API の入力データはモデルの学習に使われない。 Team / Enterprise や商用 API では、プロンプトも出力もアップロードファイルも Anthropic の基盤モデル学習に利用されない（Zero Training by Default）。
  2. エンタープライズ向けの監査・統制機能が標準で揃っている。 SSO / SCIM による ID 管理、Enterprise Audit Logs と Compliance API による SIEM 連携、カスタムデータ保持期間の設定により、CISO の監査要件を満たせる。
  3. 規制要件や閉域網要件が厳しい場合は、Bedrock / Vertex AI の選択肢も即座に提示する。 医療（HIPAA / BAA）や金融など厳格な業界でも、標準コンプライアンス文書（SOC 2 Type II / DPA）やクラウド環境統合によって解決策を示せる。

30 秒で全体像

flowchart TD
  O[顧客のセキュリティ懸念] --> T1[学習利用への懸念<br>Zero Training by Default / DPA]
  O --> T2[規制・認証の懸念<br>SOC 2 Type II / HIPAA BAA / GDPR]
  O --> T3[可視化・統制の懸念<br>SSO / SCIM / Audit Logs / Compliance API]
  O --> T4[閉域網・データ滞留の懸念<br>Custom Retention / Bedrock / Vertex AI]

用語意味
Zero Training by Default商用プラン（Team / Enterprise）および API に入力されたデータをモデル学習に使わない原則
SOC 2 Type IIセキュリティや可用性等の統制が一定期間適切に運用されていることを示す第三者監査報告書

本編

3-1 よくある 5 大セキュリティ反論と切り返し

顧客の懸念（Objection）相手の心理・リスク適切な切り返し（Counter-Objection）
1. 「入力した社内データがモデルの学習に使われませんか？」競合他社への機密漏洩リスクを恐れているClaude Team / Enterprise および商用 API は Zero Training by Default であり、顧客データは学習に一切使われません。DPA や Trust Center の情報も提示できます
2. 「金融・医療など規制産業のため、SOC 2 や HIPAA 対応が必須です」社内ベンダー審査に通らない、法令違反になるSOC 2 Type II を取得済みです。医療・ライフサイエンス分野では HIPAA 対応と BAA の締結、EU 関連では GDPR 準拠の DPA に対応できます
3. 「社員が何を入力しているか監査・SIEM 連携できません」内部不正や情報流出の追跡・eDiscovery ができないClaude Enterprise には Enterprise Audit Logs と Compliance API があり、活動履歴や会話内容を SIEM へ連携でき、ID 管理も SSO / SCIM で統制できます
4. 「開発者が Claude Code でソースコードを扱うのが心配です」社内コードの外部流出や設定統制の欠如Enterprise 契約配下で Claude Code も統合管理でき、managed-settings.json 等による設定強制が可能です。さらに AWS Bedrock 等の VPC 閉域環境 での運用も選べます
5. 「無期限にデータが残ると社内保持ポリシーに反します」不要データの長期保管による漏洩リスク増大初期設定ではデータ消失防止のため保持されますが、Enterprise 管理者が Custom Data Retention により自動削除期間を自社規定に合わせて設定できます

3-2 審査をスムーズに通す営業のコツ

  • 審査資料を早期に出す: 商談が最終局面に入ってから「SOC 2 報告書が欲しい」となると数週間遅れるため、IT・セキュリティ部門が関与した時点で Trust Center や NDA 下の監査資料、DPA / BAA の案内を先回りで共有します。
  • クラウド選択肢を「逃げ道」として持っておく: SaaS 型の審査がどうしても社内規定で厳しい顧客には、すでに承認済みの Amazon Bedrock / Google Cloud Vertex AI 経由での導入を即座に提案できるようにしておきます。

まとめ：どう判断するか

状況避ける選択とるべき選択

CISO が「従業員の AI 利用をすべてログ監視したい」と要望「チャット画面を目視で確認してください」と答えるEnterprise Audit Logs と Compliance API を使った SIEM 連携を説明する

問 1

A. データ保持期間は全社固定で変更できないため、導入は不可能である

第 4 章 ROI 設計と全社拡大戦略（Pilot ROI & Enterprise Expansion）

💡 ヒント

この章のたとえ：「契約＝ゴール」ではなく「更新・拡大＝本番」のリレー

最初のパイロット契約や 100 シートの受注で営業が手を引いてしまうと、顧客社内では 30-Day Fade が起きて翌年の更新時に解約されてしまいます。契約前から投資対効果（ROI）の物差しを握り、導入後は Champion Network と職種別トレーニングで定着させ、次の部門へ価値を広げていく一連の流れが Claude Sales の勝負どころです。

この章のゴール

  • パイロット開始前に Baseline Metrics・Success Metrics・ROI Scorecard を顧客と合意する営業上の意義を説明できる。
  • First Slice によるスモールスタートと、本契約・全社展開への橋渡しを設計できる。
  • 導入後の 30-Day Fade を防ぐ 3 フェーズ（Activation / Acceleration / Expansion）と Champion Network の役割を説明できる。
  • パートナー企業自身の Claude Partner Network（CPN） ティア維持・昇格と認定資格・導入実績のつながりを理解する。

要点 3 つ

  1. 売る前から「成功の証明方法（ROI Scorecard）」を合意する。 導入前の業務時間・件数・コストを Baseline として記録し、パイロット終了時に投資対効果を経営層へ説明できる材料を最初に仕込む。
  2. 受注後の 30-Day Fade を防ぐ仕組みをセットで提案する。 ライセンス販売だけでなく、Champion Network 構築や職種別トレーニング（Role-Based Training）を組み込むことで、継続利用とアップセルにつながる。
  3. Activation → Acceleration → Expansion の 3 段階で全社へ広げる。 初期部門の定量成果を社内事例化し、Engineering・Legal・Finance・CS などの隣接ワークロードへ計画的に拡大する。

本編

4-1 決裁者を納得させる ROI Scorecard の作り方

経営層（CIO / CFO / 事業部長）は「AI が賢いかどうか」ではなく「投資に見合うリターンがあるか」で予算を決めます。

項目具体的に押さえる数値営業上の効果
現状コスト（Baseline）対象業務の月間件数 × 1 件あたりの平均作業時間 × 人件費単価「放置している現在の見えないコスト」を可視化できる
改善目標（Success Metrics）処理時間の短縮率（例：40% 削減）、一次回答精度、レビュー待ち時間パイロット終了時の「合格・本番移行」の判断基準がぶれない
投資コスト（Investment）ライセンス費用（シート単価 × 人数）または API 利用料 ＋ 初期導入支援費費用対効果（回収期間・ROI 倍率）を明確に算出できる

4-2 導入後の定着と拡大（Activation → Acceleration → Expansion）

  1. Activation（立ち上げ期）: SSO / SCIM 連携、カスタム保持期間の設定、利用ポリシーの周知を完了し、First Slice の対象チームが迷わず使い始められる状態を作ります。
  2. Acceleration（定着加速期）: 30-Day Fade を防ぐため、各部門に Champion を立てて専用チャットチャネルで質問を受け付け、Role-Based Training で実務直結の成功体験を広げます。
  3. Expansion（全社拡大期）: 初期部門で達成した ROI Scorecard の実績をもとに経営報告を行い、次の高価値部門（開発・法務・財務・営業・CS）へのシート追加・API 連携を提案します。

4-3 パートナー企業としての CPN 連携

パートナー企業の営業・コンサルタントにとって、顧客の成功は自社のパートナー地位向上にも直結します。Claude Partner Network（CPN）では、認定資格の取得数やエンタープライズ導入の実績が Select / Preferred / Global Premier といったティア要件と連動しており、販売して終わりではなく定着と拡大まで伴走することが双方の利益になります。

まとめ：どう判断するか

状況避ける選択とるべき選択

パイロットで年間 5,000 時間相当の削減効果が確認できたパイロット部門の担当者へお礼を言って完了とする成果を ROI Scorecard にまとめて経営層へ報告し、他部門への Expansion 商談へつなぐ

問 1

B. パイロット開始前に現状業務の Baseline Metrics と達成目標の Success Metrics を定義し、経営会議で説明できる ROI Scorecard を作成する計画を組む

D. モデルの説明だけを書いた技術論文を配布する

B。30-Day Fade は「自分の日常業務にどう使うか分からない」「困ったときに聞ける相手がいない」ことで起きます。Champion Network と職種別トレーニングによる定着支援が最も効果的です。

総合確認問題（シナリオ形式）

総合問 1（ポジショニング ＋ セキュリティ反論）

従業員 2,000 名の金融サービス企業から「社内で個人の生成 AI アカウントが使われており情報漏洩が心配だ。全社で統一環境を導入したいが、全社標準は AWS であり、社員の利用ログは既存の SIEM へ取り込みたい。また入力データがモデルの学習に使われない保証も必須」と相談を受けました。営業担当として最も適切な提案の組み合わせはどれですか。

A. 個人向け Pro プランを全員に配布し、パスワードを複雑にするよう通達する
B. 社員の日常業務向けには SSO・Audit Logs・Compliance API・Zero Training を備えた Claude Enterprise を提案し、自社システム連携や閉域網ワークロードには Amazon Bedrock の併用も選択肢として示す
C. Free プランのブラウザ利用を推奨し、週 1 回スクリーンショットを提出させる
D. セキュリティ要件が厳しいため、AI 導入自体を見送るよう助言する

解答

B。Shadow AI の解消と SIEM 監査・学習除外の要件には Claude Enterprise が適合し、AWS 標準の自社システム連携や閉域網要件には Amazon Bedrock を組み合わせるのが実務的な最適解です。

総合問 2（Discovery ＋ Land and Expand ＋ ROI）

ある製造業の顧客が「全社で Claude を導入したいが、役員会が投資対効果に懐疑的で予算が通りにくい」と悩んでいます。商談を前進させる提案戦略として最も適切なものはどれですか。

A. 「他社もみんな使っているので大丈夫です」と精神論で説得する
B. まず効果を測定しやすい 1〜2 部門を Land（着地）対象に選び、導入前の Baseline と達成基準の Success Metrics を定義した ROI Scorecard を作成して、短期パイロットの実績をもとに全社拡大（Expand）を図る
C. 役員会を通さずに現場の経費で 1 アカウントずつ購入してもらう
D. 全社予算が下りるまで 2 年間待つ

解答

B。懐疑的な決裁者には Land and Expand で初期投資とリスクを抑えつつ、Baseline と ROI Scorecard で定量効果を証明する提案が最も効果的です。

総合問 3（定着支援 ＋ 規制要件）

ヘルスケア関連企業で Claude Enterprise の導入が決まり、HIPAA 対応の BAA も締結しました。しかし営業担当は契約締結と同時に次の新規案件へ移り、顧客社内へのトレーニングや推進体制は一切組まれませんでした。2 か月後に予想される最大のリスクと、本来とるべきだった対策はどれですか。

A. HIPAA の法律が自動的に無効になるため、毎日契約書を再締結すべきだった
B. 導入初期の関心が薄れて利用率が急落する 30-Day Fade が起きやすいため、部門別 Champion Network の設置と職種別トレーニング（Role-Based Training）を組み込んでおくべきだった
C. ライセンス費用が自動的に 10 倍になるため、全アカウントを停止すべきだった
D. 監査ログが消滅するため、紙のノートで記録すべきだった

解答

B。契約とコンプライアンス対応が完了しても、現場での使い方支援と推進体制がなければ 30-Day Fade が起きて更新・拡大に失敗します。Champion Network と職種別トレーニングの伴走が不可欠です。
