# 直前チェック

8つの試験分野の判断を1枚で見直すための最終チェックシートです。各行は「✕ 選ばない（ひっかけ）」と「○ 選ぶ（本番の正解パターン）」の二択になっています。

## 1. 高度なエージェントアーキテクチャとオーケストレーション（[第1章](01-高度なエージェントアーキテクチャとオーケストレーション.md) · 17%）

| 場面 | ✕ 選ばない | ○ 選ぶ |
| --- | --- | --- |
| サブエージェントの連携 | 親の会話履歴を全部コピーする | コンテキスト分離し、必要な前提・ID・出力形式だけ渡す |
| 高リスク・不可逆な操作 | プロンプトに「確認してから実行」と書く | 実行前に一時停止する Human-in-the-Loop 承認ゲートを置く |
| 長時間エージェントの中断・再起動 | インメモリ変数だけに状態を保持し最初からやり直す | チェックポイント＋セッション永続化＋べき等性キーで未完了から再開 |
| 定型処理が9割のエージェント | モデルサイズを上げて自律のままにする | トレース分析に基づき定型部分をワークフロー型へ切り出す |
| コンテキスト上限・コスト逼迫 | クライアント側で `system` を毎ターン書き換える | `system` 固定でキャッシュ維持＋Context Editing / Compaction / 永続メモリ |
| 100個以上の大規模ツールカタログ | 全ツール定義を毎回リクエストに載せる | `tool_search`（遅延ロード）で必要ツールのみ動的に読み込む |
| サブエージェントのスキルと選定 | テスト実行を委任し、組み込みエージェントでスキルが動く前提にする | 中間作業が不要な探索に絞り、スキルはカスタムエージェントの `skills:` に明示列挙する |
| Managed Agents のストリーム開始 | `events.send()` の後に `events.stream()` を開く | 必ず `events.stream()` を先に開いてから `events.send()` を送る |

## 公式サンプル問題3問の最終確認

試験ガイド（セクション7）に掲載されている公式サンプル問題の判断ロジックを、そのまま復習できます。

| 問題 | 問われた核心 | 正解の理由 |
| --- | --- | --- |
| **サンプル1（分野2）** | `429`・`max_tokens`・モデル拒否が同じリトライ経路に混在し、コスト急増と短い応答が発生 | **停止条件に応じて分岐する**。レート制限はバックオフ再試行、長さ超過は出力上限引き上げ、拒否は安全処理経路へ回す |
| **サンプル2（分野5）** | ペア比較ジャッジが人間と約半分しか一致せず、先に表示された応答ばかり選んでいる | **順序をランダム化し、人間ラベルとの一致度を測り直し、許容水準になるまでゲート権限を与えない** |
| **サンプル3（分野7）** | チケット内の隠された指示で別顧客の CRM 情報を外部メール送信された（プロンプト対策は実施済み） | **メール宛先許可リストまたは人間承認、CRM アクセスを当該チケットのアカウントに限定する**（モデル外部の決定論的制御） |
